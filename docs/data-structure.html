EcoSmart Open Marketplace Data Structure

This is the plain list of information EcoSmart must remember. Every record should have a unique ID, a creation date/time, and a last-updated date/time unless stated otherwise.

1. User account

One account for a waste generator, recycler, or EcoSmart administrator.

  • User ID
  • Role: generator, recycler, or administrator
  • Full name
  • Email address
  • Email-verification status: unverified or verified
  • Area/neighbourhood
  • Approved contact details, shown only to a matched party
  • Account status: active, pending recycler approval, rejected, or suspended

2. Email verification

A one-time email verification attempt for an account email address.

  • Email-verification ID
  • User ID or pending registration ID
  • Email address
  • One-time email code reference
  • Status: sent, verified, expired, or failed
  • Email sent and verified date/time

3. Recycler verification application

Information submitted before a recycler can receive listings or make offers.

  • Recycler-verification ID and recycler user ID
  • Recycler name and phone number
  • Government ID type, number, and document/file reference
  • Recycler photo file reference
  • Licence or registration type, number, and document/file reference
  • Submitted area/neighbourhood
  • Approval status; reviewing administrator; review date/time; approval/rejection note

4. Supported material catalogue

The administrator-managed pilot catalogue.

  • Material ID and material name: cardboard, PET plastic bottles, aluminium, brass, or glass
  • Active/inactive and recyclable status
  • Recycling guidance/tip
  • Catalogue change date/time and administrator who changed it

5. Recycler material and buying estimate

One recycler’s buying settings for one supported material.

  • Setting ID, recycler user ID, and material ID
  • Accepted/not accepted status
  • Estimated buying price in naira and unit: per kilogram, per item, or per bag
  • Estimate-not-final-offer label
  • Availability, recycler area/neighbourhood, effective-from and ended date/time

Prior settings provide dated estimate history for a later build.

6. Material intake attempt

Each time a generator checks an item before listing it.

  • Material-intake ID and generator user ID
  • Intake method: scan, photo upload, or manual selection
  • Uploaded image/file reference, system suggestion, and confidence result
  • Generator’s final selected material ID
  • Outcome: continued to matching or not supported in this pilot
  • Guidance/tip version shown

7. Media file

A reference to an uploaded photo or document.

  • Media-file ID and owner user ID
  • Linked record type and ID
  • Media type: photo or document
  • Storage reference/file URL, original file name, and upload date/time

8. Recycler match result

A saved snapshot of recyclers shown for a selected material.

  • Match-result ID; material-intake or listing ID; generator and recycler user IDs
  • Areas, selected material, and recycler availability used for matching
  • Estimated price and unit shown at match time
  • Match date/time and status: shown, selected, or not selected

9. Listing

A request sent to one selected recycler only.

  • Listing ID; generator and selected recycler user IDs; material and linked intake IDs
  • Description, listing photo references, declared quantity and unit
  • Location, generator area/neighbourhood, and pickup/drop-off preference
  • Status: draft, sent, accepted, declined, handover arranged, inspected, funded final offer, completed, rejected, or expired
  • Sent date/time

10. Recycler response and handover arrangement

The recycler’s decision and agreed exchange method.

  • Response ID, listing ID, and recycler user ID
  • Accepted/declined response, decline reason, and response date/time
  • Agreed pickup/drop-off arrangement and arrangement note
  • Contact-details-shared date/time

11. Inspection record

The recycler’s inspection after direct pickup or drop-off.

  • Inspection ID, listing ID, and recycler user ID
  • Inspection date/time
  • Actual weight/quantity and unit
  • Inspection note

12. Final offer

The funded final offer after inspection.

  • Final-offer ID; listing, recycler, generator, and inspection IDs
  • Final amount in naira and currency NGN
  • Funding status; offer status; sent date/time; 24-hour expiry
  • Generator decision, decision date/time, and rejection reason

13. Wallet payment record

Every payment-provider movement for a final offer.

  • Payment ID and final-offer ID
  • Payer recycler and payee generator IDs
  • Payment type: recycler funding, generator payout, or funding return/unavailable
  • Amount, currency, commission amount always zero in pilot
  • Provider name/reference, payment status, initiation/confirmation date, and failure/reversal reason

14. Transaction event history

The time-stamped record of important actions.

  • Event ID; listing and final-offer IDs; event type; actor
  • Previous and new listing/offer statuses
  • Related payment, inspection, response, or match record
  • Event date/time and note

15. In-app chat message (Should have)

A message between the matched parties for an active listing.

  • Message ID, listing ID, sender and recipient IDs
  • Message text, sent date/time, and delivery/read status

16. In-app call session (Could have)

A call invitation or call between matched parties.

  • Call-session ID, listing ID, initiating and invited user IDs
  • Call status: invited, accepted, declined, ended, or failed
  • Started and ended date/time

17. Administrator action

An administrator change to profiles, materials, or records.

  • Administrator-action ID and administrator user ID
  • Action type, affected record type/ID, action note, and action date/time

18. Pilot measurement record

A record used to assess the pilot.

  • Measurement ID and type
  • Related user, listing, final-offer, or payment ID
  • Measured value where needed and recorded date/time

Important relationships

  • A user account can be a generator, recycler, or administrator; a recycler has one verification application and many material settings.
  • One supported material can be accepted by many recyclers and used in many intake attempts and listings.
  • One intake attempt can lead to many match results and one listing.
  • One listing has one selected recycler, one response, one handover arrangement, zero or one inspection, zero or one final offer, and many event records.
  • One final offer has one inspection, many payment records, and one generator decision.
  • Chat messages and calls belong only to an active listing shared by matched parties.

Deliberately not stored for this pilot

  • Commission calculations beyond the zero commission required in the free pilot.
  • Precise map coordinates or distance-based matching.
  • A claim that a scan correctly identifies every item.
  • Transport, storage, ownership transfer, dispute adjudication, insurance, litigation, ratings, or advertising records.
